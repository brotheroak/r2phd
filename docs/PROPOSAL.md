# IntentSpec · .EXE-THON 기획서

## 1. 풀고 싶은 문제

자연어로 적은 분석 의도가 데이터 처리(SQL·집계)로 넘어가며 깨지는 문제.

- **누가**: 품질·임상·연구 데이터 분석자와 그 결과를 리뷰하는 팀장/동료
- **언제**: LLM이 SQL을 만들어 주고가 “정상 실행”된 직후
- **얼마나**: 용어·날짜·식별자를 사람이 대조하는 데 분석 1건당 수십 분. 놓치면 틀린 실패율이 회의 자료에 고정됨

예시 함정

1. 같은 `lot_no`라도 `product_code`가 다르면 다른 로트인데 단독 조인
2. “최근”을 `ingest_date`(적재일)로 잘라 시험일이 오래된 건이 섞임
3. `PASS_AFTER_RETEST`를 실패로 넣어 실패율 과대

## 2. 에이전트가 해 줄 일

1. 연구 질문 + 용어 정의서 + 스키마 입력
2. **Liner Model API**로 개념·조건·예외 추출, 모호함 목록 생성
3. **Liner Scholar Search**로 방법론 근거 보강
4. 연구자가 옵션을 확정 → 분석 명세 + SQL + 검증 항목 컴파일
5. 결과 CSV를 감사해 **의도 드리프트 점수**와 근거 행 제시

## 3. Liner API 활용

| API | 핵심 기능 |
| --- | --- |
| Model (`liner-gpt-router`) | analyze / confirm / audit |
| Scholar Search | 모호 용어 학술 근거 |

키가 없으면 동일 시나리오의 데모 엔진으로 시연 가능.

## 4. 확장성 · 임팩트

제조·임상뿐 아니라 재무(미수금), 행정(민원 기간), 물류(출하 기준일) 등
“정의가 애매한 자연어 분석 → 구조화 명세” 패턴 전반에 재사용 가능.
